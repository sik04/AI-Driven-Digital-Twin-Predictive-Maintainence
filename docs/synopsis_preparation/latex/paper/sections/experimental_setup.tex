\section{Experimental Setup}
\label{sec:experimental_setup}

\subsection{Benchmark Datasets and Engine-Level Partitions}
\label{subsec:datasets_splits}
We evaluate IntelliTwin on three benchmark sub-datasets from the NASA C-MAPSS turbofan engine degradation simulation suite \cite{saxena2008damage}:
\begin{enumerate}
    \item \textbf{FD001}: Single sea-level operating condition, single failure mode (HPC degradation), comprising 100 run-to-failure engine trajectories.
    \item \textbf{FD002}: Six diverse operating flight conditions, single failure mode (HPC degradation), comprising 260 engine trajectories.
    \item \textbf{FD004}: Six diverse operating flight conditions, two concurrent failure modes (HPC and fan degradation), comprising 249 engine trajectories.
\end{enumerate}

To prevent temporal and engine-level data leakage, partitioning is strictly executed at the engine level using a fixed master seed ($2026$) prior to any data preprocessing (50\% training, 20\% calibration, 10\% validation, 20\% held-out test):
\begin{itemize}
    \item \textbf{FD001} (100 engines): 50 training, 20 calibration, 10 validation, and 20 held-out test engines.
    \item \textbf{FD002} (260 engines): 130 training, 52 calibration, 26 validation, and 52 held-out test engines, stratified across engine lifetime quartiles ($Q_1$--$Q_4$).
    \item \textbf{FD004} (249 engines): 124 training, 50 calibration, 25 validation, and 50 held-out test engines.
\end{itemize}
Across all three datasets, 304 engines are allocated to training, 122 to calibration, 61 to validation, and 122 to final held-out testing (total 609 engines).

\subsection{Feature Space and Causal Windowing}
The raw engine streams comprise 3 operational settings and 21 sensor measurements per cycle. Preprocessing applies training-only z-score normalization ($x_{\text{normalized}} = (x - \mu_{\text{train}})/s_{\text{train}}$, with $\text{ddof}=0$ and $s=1.0$ if $\sigma=0$). A locked 17-feature selection is enforced: 3 operational settings and 14 qualified degradation sensors. Seven sensors are excluded under the recorded qualification procedure; we do not claim they are universally uninformative across all domains.

Temporal trajectories are windowed with an exact causal horizon of $w=30$ cycles, unit stride ($s=1$), and strict avoidance of padding or crossing engine boundaries. Training targets use the modeling convention $\min(\text{rul\_true}, 125)$ cycles, while calibration, validation, and test splits evaluate true uncapped RUL.

\subsection{Base Degradation Predictors}
Two point-prediction architectures operate on identical 30-cycle causal horizons:
\begin{enumerate}
    \item \textbf{Gradient Boosted Regressor (GBR)}: \texttt{sklearn.ensemble.HistGradientBoostingRegressor} operating on C-order flattened $30 \times 17 = 510$-dimensional vectors. Selected configs: \texttt{gbr\_lr010\_leaf15\_l2\_0} (FD001) and \texttt{gbr\_lr010\_leaf31\_l2\_0} (FD002, FD004).
    \item \textbf{Long Short-Term Memory (LSTM)}: Single-layer unidirectional PyTorch LSTM ($H=64$, recurrent dropout $0.0$, followed by \texttt{nn.Dropout(p=0.20)} and \texttt{nn.Linear(64, 1)}, learning rate $\eta=0.0010$, \texttt{lstm\_h64\_lr0010}) with early stopping on validation uncapped RMSE.
\end{enumerate}
Each configuration is trained across five random seeds ($2026, 2027, 2028, 2029, 2030$), producing 30 frozen base model checkpoints in the registry.

\subsection{Calibration Variants and Pre-Registered Controls}
On the reserved calibration engine splits, we evaluate three conformal calibration variants: \texttt{global\_hcp}, \texttt{regime\_hcp}, and \texttt{decision\_aware\_hcp}.

To rigorously evaluate RQ3, four named controls across three distinct baseline families are pre-registered:
\begin{enumerate}
    \item \textbf{Matched-Width Interval (\texttt{matched\_width\_interval})}: Sources from \texttt{global\_hcp} or \texttt{regime\_hcp}, scaling unclipped half-width by $\lambda \in [0.01, 4.0]$ (plus $\{5, 6, 8, 12, 16\}$): $L_\lambda = \max(0, p - \lambda q_{\text{source}}), U_\lambda = p + \lambda q_{\text{source}}$. Selected on FD002 validation data to match proposed validation MPIW within $\le 1.0$ cycle: GBR selects \texttt{global\_hcp} with $\lambda=0.92$; LSTM selects \texttt{regime\_hcp} with $\lambda=0.90$.
    \item \textbf{Widened Interval (\texttt{widened\_interval})}: Same scaling formula with $\lambda \ge 1.00$, minimizing validation cost: GBR selects \texttt{regime\_hcp} with $\lambda=1.00$; LSTM selects \texttt{global\_hcp} with $\lambda=1.00$.
    \item \textbf{Point Safety Margin (\texttt{point\_safety\_margin})}: Maintains iff $p \le 1 + m$ for $m \in \{0, \dots, 250\}$, minimizing validation cost: GBR selects $m=5$; LSTM selects $m=4$. As a point policy, width and conformal coverage are not applicable (\texttt{NOT\_APPLICABLE}).
    \item \textbf{Earlier Intervention (\texttt{earlier\_intervention})}: Maintains iff $L_{\text{source}} \le h$ for $h \in \{1, \dots, 251\}$, minimizing validation cost: GBR selects \texttt{regime\_hcp} with $h=1$; LSTM selects \texttt{global\_hcp} with $h=1$.
\end{enumerate}

\subsection{Maintenance Simulation and Cost Scenarios}
Sequential policy execution is evaluated using the discrete-event simulator. The primary economic scenario (\texttt{primary\_reference}) specifies:
\begin{equation}
\CPM = 1.0~\SCU, \quad \CFAIL = 5.0~\SCU, \quad \CWASTE = 0.20~\SCU/\text{cycle}
\end{equation}
Sensitivity scenarios evaluate \texttt{failure\_sensitive} ($\CFAIL=10.0~\SCU$) and \texttt{waste\_sensitive} ($\CWASTE=0.40~\SCU/\text{cycle}$). 

The primary policy triggers \texttt{MAINTAIN\_NOW} at cycle $t \in [30, T-1]$ if and only if $L(t) \le 1.0$ cycle. Preventive maintenance occurs immediately upon decision and terminates the episode (zero intervention lead time). If maintenance occurs at $t < T$, cost is $\CPM + \CWASTE \times (T - t)$; if no maintenance occurs before failure ($t=T$), cost is $\CFAIL$ with wasted life $W=0$. Offline interval evaluation includes all qualified endpoints $30$ through $T$. The equality values (20, 45, and 10 cycles) compare preventive-plus-waste cost with failure cost, and do not represent policy decision thresholds.

\subsection{Statistical Inference and Decision Protocol}
Hypothesis testing uses paired engine-level cluster bootstrap inference:
\begin{itemize}
    \item \textbf{Resampling Engine}: $B = 10{,}000$ paired engine-cluster bootstrap resamples with replacement, stratified by frozen engine lifetime quartiles ($Q_1$--$Q_4$), using \texttt{PCG64} PRNG with seed sequence \texttt{SeedSequence([2026, 6, dataset\_number])}.
    \item \textbf{Weighting}: Engines receive equal weighting; seeds are averaged within engines as descriptive training variability, not independent sampling units.
    \item \textbf{Missing-Group Bound Propagation}: If an eligible group ($\ge 10$ engines) is absent in a bootstrap resample, its absolute coverage error is bounded by $[0.0, 0.90]$ at 90\% nominal coverage and propagated conservatively.
    \item \textbf{Confirmatory Decision Intervals}: $98.75\%$ percentile intervals (quantiles 0.00625 and 0.99375), providing Bonferroni family-wise error rate control ($\alpha = 0.05/4 = 0.0125$) across RQ1--RQ4.
    \item \textbf{Intersection-Union Test (IUT)}: Benefit conditions pass if lower $\text{CI} > \text{margin}$; ceiling/noninferiority conditions pass if upper $\text{CI} < \text{ceiling}$. Equality with a boundary or degenerate inference is inconclusive. Failure safeguard uses observed fleet failure rates ($\Deltafail \le 0.0$). An RQ is \texttt{Supported} only if all required components pass, \texttt{Unsupported} if any fails, and otherwise \texttt{Inconclusive}.
\end{itemize}
